# AgentClinic × SkillOpt-Lite evaluator

This experiment treats SkillOpt-Lite as a **version-change generator** for an
AgentClinic skill artifact. It does not modify AgentClinic core code and it does
not make skills part of the model API. The evaluator injects a candidate skill
through `AgentClinicAdapter`, runs a fixed dataset split, and exports the file
contract expected by the SkillOpt-Lite optimization loop.

## What stays fixed

- AgentClinic scenario, patient, measurement, and moderator behavior
- deterministic train/validation/test case IDs from `splits.toml`
- the selected model and optional harness configuration
- binary AgentClinic correctness as both `hard` and `soft` until a validated
  continuous clinical grader is introduced

## What changes

- `skill.md`: the candidate diagnostic skill generated by the optimizer
- optionally, a separately versioned harness TOML selected with `--harness`

The skill and harness remain independent experimental dimensions. A SkillOpt
run should optimize the skill while keeping the harness fixed; a later
HarnessOpt run can do the converse.

The default control uses AgentClinic's original generative measurement agent
and no harness artifact. `grounded_measurement_v001.toml` is an optional
measurement ablation and must be reported as a separate condition.

## Safe contract dry-run

From the repository root:

```bash
python -m skill_harness.methods.skillopt_lite.evaluator \
  --skill skill_harness/artifacts/seeds/diagnostic_reasoning/v000.md \
  --dataset MedQA \
  --split train \
  --eval_limit 2 \
  --limit 2 \
  --contract_dry_run
```

`--contract_dry_run` constructs the real prompts and output artifacts but never
calls a model API. Its scores are deliberately zero and must not be used as
experimental results.

## Small live evaluation

After configuring the model credentials used by AgentClinic, remove
`--contract_dry_run`:

```bash
python -m skill_harness.methods.skillopt_lite.evaluator \
  --skill skill_harness/artifacts/seeds/diagnostic_reasoning/v000.md \
  --dataset MedQA \
  --split train \
  --eval_limit 5 \
  --limit 5 \
  --doctor_llm deepseek-v4-pro \
  --patient_llm deepseek-v4-flash \
  --measurement_llm deepseek-v4-flash \
  --moderator_llm deepseek-v4-flash
```

Run validation for selecting a skill version and reserve test for the final
comparison. The default split is deterministic 20% train, 20% validation, and
60% test. When `--eval_limit` is set, a fixed seed samples cases from that split.

After the initial five-case debug pilot, use `splits_clean_v1.toml` for training
runs. It keeps the original train/test sets but excludes the five validation
cases whose contents were exposed during debugging, leaving 16 clean gate cases.

## Output contract

By default, generated files live under the ignored directory:

```text
skill_harness/results/skillopt_workspaces/agentclinic/<doctor-model>/
├── skill.md
└── .skillopt/
    ├── samples/
    │   ├── failed/*.md
    │   └── passed/*.md
    └── _eval_run/<split_timestamp>/
        ├── results.jsonl
        ├── metrics.json
        ├── split_manifest.json
        └── predictions/<case-id>/
            ├── conversation.json
            ├── target_system_prompt.txt
            └── target_user_prompt.txt
```

Each `results.jsonl` row includes the SkillOpt-Lite-required `id`, `hard`, and
`soft` fields plus AgentClinic-specific fields such as diagnosis, number of
doctor turns, requested tests, failure reason, trajectory, and skill/harness
version metadata. It also records observed model calls and backend retry/empty
response health so infrastructure failures are not confused with skill errors.
The CLI ends with a parseable line of the form:

```text
Results: hard=0.4000 soft=0.4000
```

To resume an interrupted run, reuse the exact `--output_dir` and add `--resume`.
Existing case IDs are skipped.

## Paired validation gate

Compare a baseline and candidate evaluated on exactly the same case IDs:

```bash
python -m skill_harness.methods.skillopt_lite.gate \
  --baseline /path/to/baseline/results.jsonl \
  --candidate /path/to/candidate/results.jsonl \
  --output /path/to/gate_report.json
```

The gate promotes only a strictly better candidate. A tie is `flat` and retains
the baseline; a lower score is `reject`. The JSON audit includes every paired
case improvement and regression. This is a pilot gate for small validation
subsets; paper-grade runs should use the full validation split.
